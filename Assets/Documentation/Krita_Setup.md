Hand-Drawn Sprite Pipeline: Krita 5.3.4 → Unity 6.3 LTS → Steam
Toolchain: Krita 5.3.4 (macOS .dmg) · Unity 6.3 LTS (6000.3.x) · KRaster Importer plugin · macOS Monterey 12.7.6

Note on "5.3.4.1": The latest confirmed 5.3.x release is 5.3.4 (Sep 16, 2026).  No separate "5.3.4.1" patch appears in the release history. You're on the correct version.

1. File Format Rules
Rule	Detail
Authoring format	.kra (native Krita — preserves layers + timeline)
Export to Unity	.png only (32-bit alpha)
Author resolution	Size for 4K output. Draw at 512×512 (or 256 for small objects, 1024 for large enemies/world objects). Unity + GPU downsample cleanly to 1080p.
Never flatten	Keep all layers in .kra through every phase
Export method	File → Export (not Save As) for any manual PNG output
Generated PNGs	Disposable — regenerated by the plugin on every re-import

2. Folder Structure
Assets/
├── Art/
│   ├── Source/           ← .kra files (NOT imported into Unity)
│   ├── Player/           ← generated PNGs land here
│   ├── Enemies/
│   └── World/
├── Animations/           ← Animation Clips
├── Prefabs/              ← character/world prefabs
├── Settings/             ← resolution presets, quality profiles, .preset files
└── Scenes/
    └── TestScene.unity   ← flat plane, all characters, for QA

Place .kra files in Assets/Art/Source/. The plugin watches them and writes generated PNGs to the matching subfolder.

3. Phased Pipeline
Core principle: Batch by phase across ALL characters before moving to the next phase. Every phase ends with a playable (progressively less ugly) build in Unity at both 1080p and 4K.

Phase 0 — Setup (one-time)
#	Action
0.1	Install Krita 5.3.4 — download krita-5.3.4-signed.dmg from krita.org, drag to Applications. (Requires macOS 10.15+; your Monterey 12.7.6 is fine.)
0.2	Install Unity 6.3 LTS (6000.3.x) via Unity Hub
0.3	Install KRaster Importer from the Unity Asset Store
0.4	Create the folder structure from §2
0.5	Camera: Orthographic. Set orthographicSize so the visible world area is identical at 1080p and 4K (the camera renders more pixels at 4K, not a wider view)
0.6	Project Settings → Player → Resolution: default 1920×1080, Fullscreen. Support 4K via in-game resolution dropdown (Phase 5)
0.7	Pixels Per Unit: 64 (512 px sprite ÷ 8 world units = 64). Verify at 4K. Lock it.
0.8	Krita canvas size = 512×512 for standard characters (256 for small objects, 1024 for large enemies). Timeline = 12 fps. Lock canvas size permanently.
0.9	Plugin config: Import method = Generate File, output path pattern = Assets/Art/{folder}/{name}_frame{n}.png, auto-reimport = Enabled, "use Krita to generate frames" = Enabled
0.10	Create a Unity Preset (Sprite Mode = Multiple, PPU = 64, Bilinear, Mipmaps ON, BC7, Alpha Is Transparency ON, Max Size 4096) and assign it to the output folders via the Preset Manager or an AssetPostprocessor script (see §5)
0.11	Create TestScene.unity: flat plane, all character prefabs running their Animators. You'll open this after every re-import at both resolutions.

Deliverable: Pipeline is wired. Dropping a .kra into Source/ auto-generates PNGs into the correct folder with correct import settings.

Phase 1 — Silhouette / Stick Figures
Goal: Validate motion, spacing, timing in-engine with zero polish.

#	Action
1.1	In Krita: one .kra per character per animation (player_walk.kra, slime_idle.kra, …)
1.2	Draw 2–4 key poses as stick figures or blocky silhouettes. Use onion skinning.
1.3	In Krita: File → Export → Animation → PNG Sequence (or use the Animation Timeline's export) as a sanity check before trusting plugin output
1.4	Save .kra → plugin auto-generates per-frame PNGs
1.5	In Unity: create Animation Clips at 12 fps, build Animator Controller with one state per animation
1.6	Open TestScene at 1920×1080 (Game view resolution dropdown) → verify motion reads correctly
1.7	Switch Game view to 3840×2160 → verify sprites are crisp, correctly scaled, no stretching

Deliverable: All characters have playable (ugly) animations in Unity at both target resolutions.

Phase 2 — Line Art / Clean Shapes
Goal: Final proportions, outlines, silhouette readability.

#	Action
2.1	In each .kra: add a new layer "lines" above the "stick" layer
2.2	Draw clean line art over existing key poses (same frame count/timing)
2.3	Optionally add in-betweens (animate on 2s)
2.4	Check line weight at both 1080p and 4K — lines should be visible but not chunky at 1080p, retain detail at 4K
2.5	Hide "stick" layer, save .kra → plugin re-imports
2.6	Open TestScene at both resolutions → verify outlines are readable, animations still correct

Deliverable: All sprites have clean, readable outlines at both resolutions.

Phase 3 — Flat Color / Base Fill
Goal: Establish palette and color-blocking.

#	Action
3.1	In each .kra: add layer "color" below the "lines" layer
3.2	Block in flat colors — 5–8 colors per character max
3.3	Keep "lines" on top, save → plugin re-imports
3.4	Open TestScene at both resolutions → verify color reads at game scale

Deliverable: Fully colored, flat-shaded sprites at both resolutions.

Phase 4 — Shading, Detail & Polish
Goal: Final art pass.

#	Action
4.1	Add layer "shade" (Multiply blend) above "lines"
4.2	Add details: eyes, accessories, texture, impact frames
4.3	Detail density should reward 4K — fine brushwork and micro-details visible at 3840×2160 that gracefully simplify at 1080p
4.4	World objects: environmental variation frames (sway, flicker, etc.)
4.5	Save → plugin re-imports
4.6	Final visual QA: screenshot at 1080p and 4K, compare side-by-side for artifacts, banding, or lost detail

Deliverable: Production-quality sprites verified at both resolutions.

Phase 5 — Optimization, Atlas Baking & Steam Packaging
#	Action
5.1	Assign sprite frames to Sprite Atlases (one per character/enemy type)
5.2	Atlas settings: Padding = 4+ px, Extrude = ON (prevents mipmap bleed between adjacent sprites)
5.3	Sprite Atlas Analyser (new in Unity 6.3): run it to find wasted atlas space, compression issues, and inefficient packing
5.4	Filter Mode: Bilinear (atlas level — overrides individual sprite settings). If you see mip-level "pop" when sprite size crosses power-of-two boundaries, switch to Trilinear
5.5	Compression: BC7 (desktop/Steam). No ASTC needed (PC-only)
5.6	Mipmaps: ON (prevents aliasing/shimmering at 1080p where sprites occupy fewer screen pixels)
5.7	Profile draw calls and texture memory in Unity Profiler at both 1080p and 4K
5.8	In-game resolution settings: dropdown with 1920×1080, 2560×1440, 3840×2160, and "Native"
5.9	UI Canvas Scaler: UI Scale Mode = Scale With Screen Size, Reference Resolution = 1920×1080
5.10	Test build on Steam at fullscreen and borderless windowed at both 1080p and 4K
5.11	Verify: no stretching, no letterboxing, no UI misalignment at either resolution
5.12	Capture Steam store screenshots at 4K for marketing
5.13	Confirm final build size is acceptable for Steam (BC7 helps)

Deliverable: Optimized, Steam-ready build verified at both resolutions.

Color Model	RGB/Alpha
Depth	8-bit integer/channel
Profile	sRGB built-in

Per-File Conventions
Convention	Rule
File per clip	One .kra per animation clip
Naming	{character}_{animation}.kra (e.g. player_walk.kra, slime_idle.kra)
Canvas size	512×512 (or as set in Phase 0). Never change after creation.
Frame rate	12 fps timeline
Workspace	Window → Workspace → Animation

Layer Stack (bottom → top)
Layer	Name	Blend Mode	Phase	Notes
1	stick	Normal	1	Hide after Phase 2
2	color	Normal	3	Below lines
3	lines	Normal	2	Always visible
4	shade	Multiply	4	Shading & detail

Krita Animation Setup (per file)
File → New → Custom Document (settings above)
Window → Workspace → Animation
In the Animation Timeline docker (bottom): click the gear icon → set Frame Rate = 12
Create your 4 layers (see table above)
In the Timeline, right-click the first cell of the stick layer → Create Blank Frame
For subsequent poses: right-click next cell → Create Duplicate Frame (copy + modify) or Create Blank Frame (new)
Toggle onion skin (overlapping circles icon in the Timeline toolbar)
File → Save As → Assets/Art/Source/Player/player_walk.kra
⚠️ Use Save As for .kra. Use File → Export only for manual PNG/video output.

5. Unity Import Settings (per sprite / preset)
Setting	Value
Texture Type	Sprite (2D and UI)
Sprite Mode	Multiple
Pixels Per Unit	64
Filter Mode	Bilinear (or Trilinear if you see mip pops)
Compression	BC7 (desktop/Steam)
Mip Maps	ON
Alpha Is Transparency	ON
Pivot	Bottom-center for ground characters (consistent per type)
Max Size	4096 (prevents auto-downscale of 512/1024 px sprites)
Sprites Per Second	12

How to apply automatically (recommended)
Create an AssetPostprocessor script — more reliable than the Preset Manager for plugin-generated files:

// Assets/Editor/AutoSpriteSettings.cs
using UnityEditor;

public class AutoSpriteSettings : AssetPostprocessor
{
    void OnPreprocessTexture()
    {
        if (!assetPath.Contains("/Art/")) return;
        if (assetPath.Contains("/Source/")) return; // skip .kra files

        var ti = (TextureImporter)assetImporter;
        ti.textureType = TextureImporterType.Sprite;
        ti.spriteImportMode = SpriteImportMode.Multiple;
        ti.spritesPerSecond = 12;
        ti.filterMode = FilterMode.Bilinear;
        ti.mipmapEnabled = true;
        ti.textureCompression = TextureImporterCompression.CompressedHQ; // BC7 on Windows
        ti.alphaIsTransparency = true;
        ti.maxTextureSize = 4096;
        ti.pixelsPerUnit = 64;
        ti.spritePivot = new UnityEngine.Vector2(0.5f, 0f); // bottom-center
    }
}

This auto-applies to every texture under Assets/Art/ (except Source/). No manual clicks, no preset UI needed.

Manual preset method (alternative)
Select a PNG in the Project window → Inspector shows import settings
Set all values from the table above
Click the preset icon (small slider/dial icon) at the top-right of the Inspector panel
In the popup: "Create New" → save to Assets/Settings/Sprite_Default.preset
Go to Edit → Project Settings → Preset Manager → add filters for *Art/Player/*, *Art/Enemies/*, *Art/World/* → assign Sprite_Default

Setting	Value

Output path pattern	Assets/Art/{folder}/{name}_frame{n}.png
Auto-reimport	Enabled (watches .kra, regenerates PNGs on change)
Animation frames	"Use Krita to generate frames" = Enabled

Krita install requirement: The plugin needs kritarunner for KRA/KRZ. The .dmg install exposes it. If the plugin can't find Krita, manually set the path in the plugin's settings panel.

8. Solo Dev Rules
#	Rule
8.1	Batch by phase, not by character — finish Phase 1 for ALL characters before starting Phase 2
8.2	Use Krita "Render Animation" (File → Export → Animation) as a sanity check before trusting plugin output
8.3	Version-control .kra files with Git LFS (they're zip archives and can be large)
8.4	Generated PNGs in Unity are disposable — regenerate anytime from source
8.5	Lock frame count early; if adding frames, append to the end of the timeline only
8.6	Maintain a TestScene with all characters on a flat plane running their Animators — open it after every re-import to catch alignment/scale issues
8.7	Always check TestScene at both 1080p and 4K before marking a phase complete
8.8	When in doubt about detail level, add it — 4K viewers will thank you, and 1080p will simply look like a clean downscale
